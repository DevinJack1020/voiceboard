# 反馈问答 / 归因 Agent：范围、实测结果与放弃项

> 本文回答三个问题：**做到哪一步、数字是多少、没做什么**。
> 所有指标来自 `scripts/run_agent_eval.py` 的真实运行结果
> [evals/results/agent_v1.json](../evals/results/agent_v1.json)；所有代码都在本仓库，可复跑。
>
> 评测分两部分：**① 15 题机制回归**跑在 30 条自造受控语料上（不是真实用户数据，只证明链路可复现）；
> **② 真实数据可用性冒烟**跑在 78 条真实公开评论上（没有问答级标注，不算准确率）。
> 两部分都**不代表线上效果**。

## 0. 一句话结论

- **做到**：SQLite 维度过滤 + 中文 bigram + BM25 的确定性检索 → 确定性模板回答（统计 + 原文引用）
  → 证据不足显式拒答 → 15 题机制回归 + 78 条真实数据冒烟 + 24 个测试；页面可用（Streamlit `pages/7_反馈问答.py`）。
- **数字（15 题受控语料）**：hit@5 **7/8 (87.5%)**、引用有效 **25/25 (100%)**、拒答正确 **4/4 (100%)**、
  误拒答 **1/11 (9.1%)**、p50 **3.52 ms** / p95 **8.67 ms**（模板路径，本机）。
- **真实数据冒烟（78 条真实评论，无问答标注）**：6 条问题里 5 条有证据、引用 **15/15** 有效、
  巴西市场问题因过滤后 0 条而正确拒答；中文问英文评论命中受限（跨语言未做，见 §2）。
- **没做到**：向量检索 / embedding、语义同义改写、跨语言、多轮追问、权限隔离、线上埋点、
  LLM 生成回答（写了可选层但默认关闭，未用真实 key 跑端到端）。

### 1.1 检索层做了什么（`src/agent/retrieval.py`）

1. **分词**：中文按**字符 bigram**（`物流太慢` → `物流/流太/太慢`），英文按单词切分，去停用词；
   不引入 jieba 等新依赖。
2. **问题解析**：把问题里的"物流/快递/包裹…""新加坡/SG""2026年10月""差评""影响大"等
   转成 SQL 过滤条件（分类、国家、商品品类、评分区间、影响度区间、日期区间）。
   多分类/多国家时**不加维度过滤**，留给对比类分别统计。
3. **打分**：BM25（k1=1.5，b=0.75，idf 上限 6），df/idf/avgdl 只在**过滤后的候选集**内计算；
   排序键 = `BM25 分 → 影响度 → 评分 → 时间 → id`，保证同分时结果稳定、可复现。
4. **聚合**：计数、平均影响、平均评分、差评占比、分类/国家分布用 SQL `COUNT/AVG/GROUP BY`
   对**过滤后全量**计算，不是对 top-k 外推。
5. **无证据**：过滤后 0 条 → `hits=()`，由回答层拒答；绝不返回"最像的几条"冒充证据。

> 一个容易误解的行为：问题里出现"包裹/快递"等词时，检索会被**收窄到物流分类**再打分，
> 所以 `aggregate.count` 是"物流维度内的全量"，不是全库。页面和回答里都会写明当前口径。

### 1.2 回答层做了什么（`src/agent/answer.py`）

**意图识别（规则，无模型）**：库外问题 → `refusal`；两个分类/国家 + 对比词 → `comparison`；
`最多/主要/为什么/痛点` → `attribution`；`多少/一共/占比` → `count`；`原话/具体/案例/抱怨` → `evidence`。

**拒答规则（确定性，写死在代码里）**：

1. 问题涉及营收/利润/GMV、竞品（亚马逊/淘宝/Shein…）、预测未来 → 直接拒答；
2. 维度过滤后 0 条 → 拒答，**不用其他市场/分类的数据替代**；
3. 证据类问题没有任何词面命中；或聚合类问题带库外主题词且没有维度可过滤 → 拒答；
4. 对比类两侧均为空 → 拒答。

拒答文案固定包含"当前库内没有足够证据回答这个问题"以及"原因/已尝试口径/为什么不做"，
不是"抱歉我不知道"式的一句话。

**引用**：每个回答的引用都是检索结果里 `Evidence` 对象本身（id + 原文 + 分类 + 国家 + 评分 + 影响度），
不做改写、不跨来源拼接；对比题每侧按影响度挑一条代表证据。

### 1.3 页面（`pages/7_反馈问答.py`）

输入问题 → 回答（拒答时黄色警告）→ 指标行（意图/是否拒答/引用数/耗时）→
证据表（feedback id、原文、分类、国家、用户类型、评分、影响度、时间、BM25 分）→
"检索口径与拒答说明"折叠面板（意图、过滤条件、问题词元、命中词、候选数、拒答规则）→
页脚边界声明。空库时显示"还没有反馈"的真实空状态，不展示虚构答案。

### 1.4 评测怎么做的（`scripts/run_agent_eval.py`）

- **语料**：脚本内置 30 条中文跨境电商反馈（6 个分类、5 个国家 SG/MY/TH/ID/US、2026-09/10），
  建临时 SQLite 库，逐题调用 `answer_question()`。
- **题目**：[evals/agent_questions_v1.csv](../evals/agent_questions_v1.csv) 共 15 题：
  聚合 4、证据 4、对比 3、应拒答 4；每题带期望证据 id、期望关键词、备注。
- **指标口径**：

| 指标 | 定义 | 本轮 |
| --- | --- | --- |
| retrieval hit@5 | 期望证据 id 是否出现在答案证据列表（≤5 条）中；只统计依赖排序检索的 8 条聚合/证据题（对比题由过滤 + SQL 聚合出答案，另算覆盖） | **7/8 = 0.875** |
| comparison_coverage | 对比题两侧各 ≥1 条证据且引用 ≥2 条 | **3/3** |
| 引用有效率 | 引用 id 属于本次检索结果、原文非空 | **25/25 = 1.000** |
| 拒答正确率 | 应拒答的 4 题中真正拒答的比例 | **4/4 = 1.000** |
| 误拒答率 | 11 条可答题中被错误拒答的比例 | **1/11 = 0.091** |
| intent_match（补充） | 回答意图是否落在期望类型（`aggregate` 含 count/attribution） | **14/15 = 0.933** |
| keyword_match（补充） | 期望关键词是否全部出现在回答里 | **14/15 = 0.933** |
| p50 / p95 延迟 | `answer_question` 单次 wall time（模板路径，本机单进程，不含 Streamlit 渲染/网络） | **3.52 / 8.67 ms** |

- **复跑**（仓库根目录，venv Python）：

```powershell
# 只跑 15 题受控回归
python scripts/run_agent_eval.py --out evals/results/agent_v1.json

# 同时跑真实数据冒烟（写入同一 JSON 的 real_data_smoke 字段）
python scripts/run_agent_eval.py --real-corpus evals/feedback_eval_v1.csv --out evals/results/agent_v1.json
```

### 1.5 真实数据冒烟（78 条真实评论，无问答标注）

- **语料**：[evals/feedback_eval_v1.csv](../evals/feedback_eval_v1.csv) 共 80 行 =
  78 条真实公开评论（Google Play 多国电商 App、中文购物评论语料）+ 2 条人工构造的 prompt injection 探针
  （`source` 以 `authored-adversarial` 开头）。
- **三个刻意的处理**：
  1. **不用 golden 标签**：`category` 由项目内置 `RuleClassifier` 对 `feedback_text + rating` 现场生成；
     `impact_level` 是该规则分类器**由 rating 推导的规则值**（含高影响词加成），**不是人工影响度标签**，
     报告与 JSON 里都注明这一点；
  2. **默认过滤 2 条注入探针**（单列报告：`--real-include-adversarial` 可放入，见 JSON 的
     `skipped_adversarial` 字段），防止对抗文本进入检索语料/LLM prompt；
  3. **country 语义按数据方说明处理**：真实集的 `country` 不是评论者自报，而是按 App 主要市场推断的中文名
     （AliExpress/Alibaba=多国（跨境）、Amazon Shopping=美国、印度电商 App=印度、中文购物语料=中国）；
     检索层做中文名↔canonical code 校正：印度→IN、美国→US、中国→CN，
     **多国（跨境）→GLOBAL 跨境专列**（不并入任何单一国家，避免"美国=0 条"式误拒）。
- **6 条固定冒烟问题与结果**（只看"能不能检索到证据、引用是否有效、该拒答时是否拒答"）：

| 问题 | 结果 |
| --- | --- |
| 物流类反馈有多少条？ | 分类过滤后 5 条，引用 3 条有效 |
| 退款相关的反馈有哪些？ | 退换货维度 12 条中取 top5，引用 3 条有效 |
| 客服相关的反馈有多少条？ | 4 条，引用 3 条有效 |
| `delivery delay or lost parcel feedback`（英文问） | 全库 BM25 检索 top5，引用 3 条有效 |
| 印度用户对物流的反馈有哪些？ | 分类+国家过滤（中文国家名校正）后 3 条，引用 3 条有效 |
| 巴西市场用户对物流的抱怨是什么？ | **正确拒答**（过滤后 0 条） |

- **汇总**：78 条入库（过滤 2 条探针）；6 题中 5 题出证据、1 题正确拒答；引用 **15/15 有效**；
  延迟 2.36–6.80 ms（本机模板路径）。
- **真实数据暴露的两个问题**（已部分处理/已记录）：
  1. 问题解析输出 canonical code，而库内 `country` 是中文市场名——已加"按库内实际取值校正"
     （印度↔IN、美国↔US、中国↔CN；多国（跨境）↔GLOBAL 跨境专列）；"未标注"不是国家，仍无法按国家过滤；
  2. 78 条中 62 条以英文为主，中文问题只能靠中文 bigram 命中少数中英混排行，**跨语言检索未做**，
     这是本轮不引入 embedding 的直接代价。
- **规则分类器在真实文本上的分布**（无 golden 泄漏的代价）：待确认 30、退换货 12、搜索推荐 11、
  商品质量 9、支付 7、物流 5、客服 4——分类覆盖面直接决定问答的维度过滤覆盖面，
  这也是 §4 把"分类质量传导"列为风险的原因。

## 2. 实测结果与真实 badcase（不粉饰）

15 题中 14 条符合预期，**1 条明确失败**；另有 1 条答案正确但过程暴露了排序弱点：

1. **q06（同义改写 → 误拒答，真实失败）**：问题"用户反映钱退不回来，这种反馈有哪些？"
   期望引用 F25"退款拖了半个月还没到账，售后一直让等"。因为"钱退不回来"与"退款"**没有字面重合**，
   BM25 命中不到，按拒答规则拒绝回答。这就是**不引入 embedding/同义词扩展的代价**。
2. **q11（对比题，答案对但代表证据排序受长度影响）**：物流侧 BM25 把较短的
   F07"物流比预计慢两天，东西倒是没坏"排在同一 token 命中的更长文本前面；
   对比题因此不把 hit@5 当指标（过滤已保证候选），而改成 `comparison_coverage` +
   "按影响度挑代表证据"的确定性策略（最终引用 F02、F22）。
3. **q13（拒答题的检索备注）**："亚马逊为什么物流比我们快？"在拒答前仍会执行一次检索，
   备注里出现 `流比` 这类**跨词边界 bigram 噪声**——它不影响拒答（拒答答案不引用），
   但说明 bigram 方案有噪声，真实数据上需要分词或字符 n-gram 调参。
4. **真实数据冒烟（§1.5）暴露的失败**：78 条真实评论中 62 条以英文为主，中文问题只命中中英混排的少数行；
   "巴西市场"问题因真实数据没有巴西市场而正确拒答。这说明"拒答规则"在真实数据上是有效的，
   但"中文问答覆盖英文语料"目前做不到——这是放弃跨语言语义检索的直接后果。

**关于"指标很好看"的诚实说明**：hit@5 87.5%、引用 100%、拒答 100% 都来自
"30 条自造语料 + 作者自己出题"的受控回归集，题目和语料一起设计，难度低于真实数据；
它证明的是**链路与口径自洽、可复现**，不是"真实线上 87.5% 正确"。
真实数据冒烟见 §1.5：因为真实数据没有问答级标注，只能证明"能检索/能引用/能拒答"，
**不能**给出真实 hit@5 或拒答正确率——这正是下一步要补的（§4）。
真实数据冒烟结果见 §1.5：跨语言限制已在真实评论上实测到（中文问英文命中低），
同义改写问题（q06）在真实数据上同样会误拒。

## 3. 放弃了什么（为什么、代价、什么时候补）

| 放弃项 | 为什么本轮不做 | 代价（已发生/预期） | 何时做 |
| --- | --- | --- | --- |
| 向量库 / embedding（faiss、chroma 等） | 会引入新依赖与索引运维；真实 78 条冒烟已暴露跨语言/同义改写会掉，但先证明"检索+引用+拒答"闭环 | 同义改写检索不到（q06 误拒）、中文问英文基本失效 | 真实数据库 >1 万条或同义改写/跨语言 badcase 占比高时 |
| jieba 等中文分词 | 禁止新增依赖；bigram 零依赖可跑 | 跨词边界噪声（`流比`），词级语义弱 | 允许依赖或改用 FTS5 + 自定义分词时 |
| LLM rerank / query rewriting | 成本、延迟、不可复现，且本轮要先有确定性基线 | 排序仍由 BM25+影响度决定 | 已有 embedding 召回后，用 LLM 做小候选 rerank |
| RAGAS / 自动评测框架 | 多数需要 LLM 判分，离线不可复现、易引入"看起来高级"但不可信的分数 | 评测维度较粗（命中/引用/拒答/延迟） | 有真实数据与人工标注后，再补答非所问/ faithfulness 抽检 |
| 多轮对话 | 需要会话状态、指代消解、上下文截断策略 | 只能单问单答；"那支付呢？"这类追问不支持 | 单问单答在真实数据稳定后 |
| 权限 / 多租户 | SQLite 单机单库，当前无登录体系 | 不能按市场/角色隔离数据（真实业务 P0） | 接真实业务数据前必须做 |
| 跨语言语义检索 | embedding 或翻译层才可能解决 | 中文问题检索英文反馈基本失效（真实评测集恰好多为英文/中英混排） | 与 embedding 一起做 |
| 流式输出 | 模板路径毫秒级返回，流式没有收益 | 无 | 若启用 LLM 回答层再考虑 SSE |
| LLM 作为默认回答层 | 幻觉/成本/联网不可复现；本轮先要可审计的确定性回答 | 回答措辞固定、不够自然 | 只作为可选增强，且保留引用白名单 + 模板回退 |

## 4. 风险与下一步（按优先级）

**P0：真实数据与口径**

- 真实数据已落盘并完成"可用性冒烟"（§1.5，78 条真实评论，过滤 2 条注入探针）；
  但**没有问答级标注**，所以还不能算真实 hit@5。下一步：给 20–30 条真实反馈人工标注
  "期望证据 / 应拒答"，补进 [evals/agent_questions_v1.csv](../evals/agent_questions_v1.csv)，
  再跑真实 hit@5 与拒答正确率。
- `category / impact_level` 是**已有分类器（规则 / DeepSeek）的输出**，不经人工修订会直接传导到
  问答统计（本例用规则分类器冒烟时，78 条里 30 条落到"待确认"）；接真实业务前要有人工修订与抽样核对。
- 选一个真实小样本做人工核对：随机 20 条回答，人工判断"证据是否真的支持结论"。

**P0：权限**——按市场/角色做行级过滤（真实业务数据不能一份库所有人看）。

**P1：embedding 检索 + 同义词/查询改写**——目标是把 q06 类 badcase 从"误拒"变成"命中"；
上线前用同一套脚本做前后对比（hit@5 ↑、误拒 ↓、引用有效不降），不允许只看命中率。

**P1：真实数据上的拒答校准**——拒答是产品决策：当前偏保守（宁可误拒）；需要真实 badcase
估计"拒答 vs 硬答"的代价，再调措辞与阈值。

**P2：多轮/澄清**——"哪个市场""再具体点"的场景，先做澄清问题（限制轮数），不做自由多轮。

**P2：线上评测与回流**——埋点问题、命中文档、拒答率、用户点赞/点踩、人工复核结果；
把 badcase 自动落成新评测题，形成回归集（本轮 CSV 就是最小版本）。

**P2：性能/索引**——数据量到几万条时加 FTS5 或本地倒排索引，仍不引入向量库；
当前每次检索全表过滤 + 打分，2000 条候选上限内毫秒级。

**已知风险**：产品/面试场景容易把"归因"理解成因果结论。本实现的归因是
"条数 × 影响度的频次/强度聚合"，模板里写死"不推断因果"，页面也有边界声明；
对外表述时应说"**反馈里最集中的问题**"，不要说"**因为 X 所以 Y**"。

## 7. 术语表（避免只堆名词）

- **bigram**：把连续两个汉字当作一个词元（`物流`、`流太`、`太慢`），无需分词词典，代价是跨词边界噪声。
- **BM25**：经典词频/逆文档频率打分（k1 控制词频饱和、b 控制长度归一化）；这里只在过滤后的候选集上算。
- **hit@5**：期望证据是否出现在前 5 条检索结果/证据里；衡量"能不能找到"，不衡量"答得好不好"。
- **引用有效率**：回答里每条引用是否真的来自本次检索结果（id 属于候选、原文非空）；衡量"有没有编引用"。
- **拒答正确率 / 误拒答率**：应拒答的题是否拒答；可答题是否被错误拒答。两者必须一起看。
- **受控语料**：评测题与语料由同一作者设计、规模 30 条，用于回归而不是泛化证明。
- **真实数据冒烟**：把真实反馈灌进临时库，用固定问题走一遍"检索 → 引用 → 拒答"，只看链路是否可用；
  没有问答级标注，所以不能算 hit@5/准确率。
- **标签泄漏**：把分类评测集的 golden 标签直接当检索/问答的输入字段，会让评测虚高；
  本项目的真实数据冒烟不用 golden 标签，分类字段由规则分类器现场生成。
- **prompt injection**：反馈文本里出现"忽略以上指令"等文本，试图让模型改行为；
  本轮默认把 2 条注入探针从检索语料中过滤，LLM 路径默认关闭且引用有白名单。
