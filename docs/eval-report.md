# VoiceBoard 分类评测报告 v1（一页版）

> 评测对象：DeepSeek 零样本分类 vs 可解释规则基线｜评测集：`evals/feedback_eval_v1.csv`（n=80）｜模型：`deepseek-flash`（非思考模式，`thinking: disabled`，`temperature=0`），prompt `deepseek-classify-v2`｜评测时间：2026-11-02（UTC 05:48–05:56）｜结果文件：`evals/results/{rule,deepseek}_v1.json`、`predictions_*.csv`、`badcases_v1.csv`

## 1. 评测集构成与标注方法

80 条公开真实电商反馈：**78 条逐字摘录 + 2 条人工构造的提示注入对抗探针**（`source=authored-adversarial`，明确标注、不冒充真实数据）。

| 类别 | 物流 | 支付 | 商品质量 | 搜索推荐 | 客服 | 退换货 | 待确认 | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 条数 | 13 | 12 | 11 | 11 | 12 | 13 | 8 | 80 |

- **来源**（逐条 `source_ref` 可核验）：AliExpress/Alibaba Google Play 评论 28 条；印度电商 App（Flipkart/Myntra/AJIO 等）Google Play 评论 29 条；Amazon Shopping App 评论 5 条；中文购物评论语料 `online_shopping_10_cats` 16 条；人工注入探针 2 条。
- **标注**：`eval-data` 单标注者（AI Agent）逐条标注主痛点与影响度（1–5），标注日期 2026-11-02，`label_note` 记录依据；**无第二标注者、无双盲、未计算一致性系数（Cohen's κ）**。
- **难例**：7 条（多意图 3、英印代码切换 1、超短 1、反讽/正负混合 1、类别边界 1）+ 注入探针 2 条。
- **局限**：① 单标注者、无一致性检验，无法区分标注噪声与模型错误；② 负向偏多（1–2 星占 70/80），会高估正向反馈表现；③ 类别比例不代表线上分布；④ 部分元数据（国家、中文语料评分/日期）为推断或占位，不用于元数据分析。

## 2. 核心指标（规则 → DeepSeek）

口径：`accuracy_business` 只在 golden 为六个业务类的样本上计算 exact match；`accuracy_e2e` 含「待确认」；`macro_recall_business` 为 6 个业务类 recall 的宏平均（仅 support>0）；`human_revision_rate_estimate` =（预测为待确认数 + 业务类误判数）/ n，是「假设全量人工复核」的离线代理指标，**不是线上真实修订率**（线上修订率由 `feedback_revisions` 实测，见应用内评测页）。

| 指标 | 规则基线 | DeepSeek 零样本 | 变化 |
| --- | ---: | ---: | ---: |
| 业务类准确率 | 56.94% | **86.11%** | +29.17pp |
| 端到端准确率 | 60.00% | **85.00%** | +25.00pp |
| 业务类 macro recall | 57.49% | **86.32%** | +28.84pp |
| 关键类召回：物流 | 38.46% | **92.31%** | +53.85pp |
| 关键类召回：支付 | 58.33% | **75.00%** | +16.67pp |
| 关键类召回：商品质量 | 63.64% | **100.00%** | +36.36pp |
| 待确认率 | 38.75% | **8.75%** | −30.00pp |
| 业务类→待确认率 | 33.33% | **1.39%** | −31.94pp |

## 3. Badcase 四层归因

归因口径：**数据**（golden 歧义/缺上下文/标注口径不一致）、**提示词**（类别边界、多意图、反讽、中英混排未被 prompt 覆盖）、**规则**（关键词未命中/误命中、多类并列、待确认阈值）、**交互**（待确认展示、人工复核路径、影响度修订入口缺失）。全部错例逐条给出 `layer / reason / proposed_fix`。

| 层 | DeepSeek 主 Badcase（12 条） | 规则基线 Badcase（32 条） |
| --- | ---: | ---: |
| 数据 | 2 | 1 |
| 提示词 | 9 | 0 |
| 规则 | 0 | 31 |
| 交互 | 1 | 0 |

代表性例子（DeepSeek 来自 `badcases_v1.csv`，规则层来自 `badcases_rule_v1.csv`）：

- **提示词层（多意图主痛点）**：FB025「…用礼品卡支付…订单取消…余额已经是零了…」golden 支付 → 预测客服（置信度 0.95）。资金损失被更长的客服对话带偏；改进：prompt 明确「资金损失 > 履约失败 > 体验受阻」的主痛点排序并加对照 few-shot。
- **提示词层（待确认判据缺失）**：FB079「…又购买了几本《数码单反摄影轻松入门》…确实很不错！」golden 待确认 → 预测商品质量（0.85）。纯好评、无业务痛点被强行归类；改进：prompt 明确「纯好评/内容评论→待确认」，不得因出现商品相关词就归类。
- **数据层（标注争议）**：FB023「已经付款2个多星期了，我还没收到书…不小心点了收货确认…」golden 支付 → 预测物流（0.90）。资金损失与履约失败的优先级在标注规约里存在张力，模型判断可被规约辩护；改进：复核该条 golden 并统一规约口径。
- **交互层（保守降级）**：FB052「…how to delete my account…」golden 客服 → 预测待确认（0.55）。模型低置信保守降级，成本落在人工复核；改进：待确认卡片展示 top-2 候选 + 一键采纳/改判并记录 revision。
- **规则层（规则基线）**：规则基线 32 条错例中 31 条在规则层，典型如 FB001「delivered/tracking/AWB 均不在词表」导致物流类零命中被降级待确认；与 DeepSeek 错例集中在提示词/数据层形成对照——规则负责可解释兜底，LLM 负责语义理解。

## 4. 成本与延迟

| 指标 | 规则基线 | DeepSeek 零样本 |
| --- | ---: | ---: |
| 调用数 / 失败数 | 80 / 0 | 80 / 0 |
| prompt / completion / total tokens | 0 / 0 / 0 | 22,597 / 3,833 / 26,430 |
| 输入/输出 token（单条均值） | 0 | 282.5 / 47.9 |
| 本次 80 条总成本（估算） | 0 元 | **¥0.0379** |
| 单批 100 条成本（线性外推） | 0 元 | **¥0.0474**（峰值时段翻倍） |
| 单条延迟 p50 / p95 | 0.057ms / 0.099ms | **896ms / 1,278ms**（mean 909ms） |

成本口径：按 DeepSeek 官方价目表（2026-11-02 抓取 `api-docs.deepseek.com`）估算，`deepseek-flash` 空闲时段输入缓存未命中 ¥1/百万 tokens、输出 ¥4/百万 tokens，按保守上限计；高峰时段（北京时间工作日 9–12/14–18）单价翻倍。非思考模式（thinking disabled）不产生额外 reasoning tokens。脚本串行调用，80 条总耗时 72.7 秒；接口层对 429/5xx/超时重试 1 次，脚本层再重试 1 次，仍失败则整批中止、不写正式结果。

> 注：曾用兼容模型名 `deepseek-chat` 预跑留档于 `evals/results/deepseek_chat_baseline_v1.json`；最终口径以 `deepseek-flash` + prompt v2 为准。

## 5. 结论与下一步

**能否上线：可以作为「AI 辅助 + 人工确认」上线，但不做全自动。** 依据：业务类准确率 86.11%、端到端 85.00%，明显优于规则基线（56.94% / 60.00%）；关键类召回 物流 92.31%、支付 75.00%、商品质量 100%；人工修订率估计从 47.50% 降至 20.00%，待确认率 8.75% 让复核量可控；成本（100 条约 5 分钱）与延迟（p95 约 1.3 秒/条）对批量导入几乎不是约束。不能全自动的原因：80 条中仍有 12 条错误，其中「待确认→业务类」过度自信 2 条，且错例集中在 prompt 未覆盖的多意图/边界（9 条）与标注歧义（2 条）。

- **规则→DeepSeek 的核心结论**：端到端 +25.00pp、人工修订率估计 47.50%→20.00%；规则的价值不在准确率，而在无网/无密钥降级、可解释基线与成本封顶。
- **仍需补测**：扩样到 150–200 条并双人标注 + Cohen's κ；按来源/语言分层报告（当前 78 条真实样本以英文 App 评论为主）；注入探针独立成文件并统计抗注入通过率；线上人工修订率实测；高峰时段与更大批量下的成本/限流表现。
- **下一步迭代**（按 Badcase 层）：提示词层补主痛点排序规则、客服↔退换货↔商品质量边界示例与「纯好评/证据不足→待确认」约束；数据层复核歧义 golden 并统一标注规约；交互层为待确认样本提供 top-2 候选一键修订；规则层补英文词形（delivered/tracking/AWB）与中英混排词表。

> 边界：这是 80 条离线小样本评测，结论只用于选型对比与 Badcase 发现，不代表线上效果；数据仅用于研究/教学/作品集演示，非商业用途。
