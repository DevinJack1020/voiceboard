# VoiceBoard｜跨境电商用户反馈与产品路线图平台设计规格

## 1. 项目目标

VoiceBoard 是一个面向跨境电商产品经理的本地单用户工作台。它把真实 CSV 用户反馈转化为可追溯的产品决策链路：

> 导入反馈 → 分类问题 → 判断影响 → 排定优先级 → 生成需求卡 → 制定迭代计划

项目以 Streamlit、Pandas 和 SQLite 为核心技术。所有指标均从用户导入并持久化的数据实时计算；首次启动为空数据库，不自动加载样例或伪造指标。

参考项目为 [Intelligent Customer Feedback Analytics](https://github.com/darshxn10x/intelligent-feedback-analytics)（MIT License）。VoiceBoard 独立实现面向产品决策的领域模型和交互，不直接复制参考项目代码。

## 2. 范围

### 2.1 本期包含

- 下载标准 CSV 模板，上传、预览、校验和确认导入。
- 使用离线规则或 DeepSeek 对反馈分类和评估影响程度。
- 按国家、用户类型和商品品类组合筛选。
- 按“出现频次 × 平均影响程度”计算问题优先级。
- 查看动态 Top 5 痛点、证据反馈和建议产品方案。
- 从痛点创建并维护需求卡，包括负责人、状态、目标版本和方案。
- 将反馈、导入批次、人工修订和需求卡持久化到 SQLite。
- 导出经过筛选的反馈、优先级结果和路线图数据。

### 2.2 本期不包含

- 登录、多租户及复杂权限管理。
- 自动抓取 Shopee 或其他第三方平台评论。
- 模型训练、模型托管或后台任务队列。
- 多人实时协作和云端部署。

## 3. 用户工作流

1. 用户在“数据导入”页下载模板，填写或整理真实反馈 CSV。
2. 系统解析文件并展示预览、字段错误、重复数量和可导入数量。
3. 用户选择“离线规则”或“DeepSeek”分类模式并确认导入。
4. 系统分类反馈、计算初始影响程度，并在同一事务中写入 SQLite。
5. 用户在“反馈明细”页筛选、查看分类来源，并人工修正分类或影响程度。
6. “优先级看板”根据当前筛选范围实时聚合六类问题。
7. 用户在“Top 5 痛点”页查看排序、证据和建议方案，并将痛点转为需求卡。
8. 用户在“产品路线图”页更新负责人、状态、目标版本和方案，或归档卡片。

## 4. 输入数据合同

CSV 采用 UTF-8 编码，标准字段如下：

| 字段 | 必填 | 类型与规则 |
| --- | --- | --- |
| `feedback_text` | 是 | 非空文本 |
| `country` | 是 | 非空文本，例如 `SG`、`MY`、`PH` |
| `user_type` | 是 | 非空文本，例如新用户、活跃用户、卖家 |
| `product_category` | 是 | 非空文本 |
| `rating` | 是 | 1–5 的整数 |
| `created_at` | 是 | 可解析为日期，存储为 ISO 8601 |
| `feedback_id` | 否 | 外部系统标识 |
| `impact_level` | 否 | 1–5 的整数；存在时优先于自动估算 |

系统拒绝缺少必填列或无法解析的文件。逐行错误会列出行号和原因；存在错误时不允许部分静默导入。重复指纹由规范化正文、国家、用户类型、商品品类和日期生成；数据库唯一约束保证重复上传不会生成重复记录。

## 5. 分类与影响程度

### 5.1 正式分类

- 物流
- 支付
- 商品质量
- 搜索推荐
- 客服
- 退换货

无法可靠映射的反馈进入内部状态“待确认”。“待确认”不作为正式业务分类参与 Top 5，用户修正为六类之一后立即进入聚合。

### 5.2 离线规则模式

分类器使用可维护的中英文关键词和短语规则。多类同时命中时依据命中权重选择最高分；并列或无命中时进入“待确认”。系统保存 `classification_source=rule`、置信度和理由。

如果 CSV 未提供 `impact_level`，初始影响程度以 `6 - rating` 计算，再根据高影响词调整，最终限制在 1–5。人工填写或后续人工修改的影响程度始终优先。

### 5.3 DeepSeek 模式

通过 OpenAI 兼容接口调用 DeepSeek。配置来自环境变量：

- `DEEPSEEK_API_KEY`
- `DEEPSEEK_BASE_URL`，默认使用 DeepSeek 官方兼容地址
- `DEEPSEEK_MODEL`

请求要求模型返回结构化 JSON：正式分类或待确认、影响程度 1–5、置信度和简短理由。返回值必须通过枚举、类型和范围校验。调用按小批次执行，设置连接与读取超时并进行有限重试。

若未配置密钥、超时、限流、余额不足或响应非法，系统不会伪装成功：页面展示可理解的失败信息，当前批次保持未写入状态，并提供改用离线规则重新处理的操作。

## 6. 优先级与 Top 5

所有分析基于当前国家、用户类型、商品品类和日期筛选范围。每个正式分类计算：

```text
frequency = 该分类反馈数量
average_impact = 该分类影响程度平均值
priority_score = frequency × average_impact
```

`average_impact` 和 `priority_score` 展示一位小数，但排序使用未舍入值。Top 5 按 `priority_score` 降序排列；同分时依次按平均影响程度、频次、固定分类顺序排序，确保结果稳定。每个痛点可展开查看构成结果的原始反馈。

建议产品方案由分类对应的可编辑策略模板初始化，不冒充 AI 自动生成内容。用户可在创建需求卡前修改方案。

## 7. 需求卡与路线图

从痛点创建需求卡时保存当时的决策快照：

- 标题与问题分类
- 频次、平均影响程度和优先级得分
- 当时的筛选条件
- 产品方案与证据摘要
- 负责人
- 状态：待评估、已规划、开发中、已上线
- 目标版本
- 创建时间、更新时间和归档时间

需求卡支持新增、查看、编辑、状态流转和归档。归档是可恢复的软删除，不直接删除历史决策。看板按状态分组，并可按负责人和目标版本筛选。

## 8. 架构与模块边界

```text
Streamlit 页面
  ├─ 数据导入 ── importer ── classifier(rule/deepseek)
  ├─ 反馈明细 ── feedback_service
  ├─ 优先级/Top 5 ── analytics
  └─ 产品路线图 ── roadmap_service
                         │
                    repository
                         │
                      SQLite
```

- `importer`：解析、字段规范化、校验、预览和重复指纹。
- `classifier`：统一分类接口；规则实现和 DeepSeek 实现可替换。
- `repository`：数据库初始化、事务和参数化 CRUD，不包含页面逻辑。
- `analytics`：筛选、聚合、优先级和 Top 5 的纯计算逻辑。
- `feedback_service`：导入编排和人工修订。
- `roadmap_service`：需求卡生命周期与字段规则。
- `app/pages`：Streamlit 展示和用户操作，不直接拼接 SQL。

数据库至少包含 `import_batches`、`feedback`、`feedback_revisions` 和 `roadmap_items` 四张表。数据库文件存放在项目 D 盘目录下的 `data/voiceboard.db`，运行时数据库不提交到 Git。

## 9. 页面设计

1. **数据导入**：空库引导、模板下载、CSV 上传、预览、校验结果、模式选择和确认入库。
2. **反馈明细**：组合筛选、分页、原文、分类来源、置信度、影响程度和人工修订。
3. **优先级看板**：实时 KPI、优先级矩阵、排序表和构成反馈钻取。
4. **Top 5 痛点**：痛点排名、证据、产品方案编辑和“转为需求卡”。
5. **产品路线图**：按状态分组的需求卡、编辑表单、负责人/版本筛选和归档入口。

空数据库、筛选无结果、全部待确认、DeepSeek 未配置等状态均使用明确说明和下一步操作，不显示虚假占位指标。

## 10. 安全与可靠性

- DeepSeek 密钥只从环境变量读取，不写入页面日志、SQLite 或版本库。
- `.env`、SQLite 文件、缓存、虚拟环境和导出文件加入 `.gitignore`。
- CSV 文件设置 10 MB 和 20,000 行上限，避免本地资源耗尽。
- 数据库查询使用参数化 SQL；写操作使用事务。
- DeepSeek 请求仅访问配置的 HTTPS Base URL，并设置超时和响应大小边界。
- 下载 CSV 时处理可能触发电子表格公式的文本前缀。
- 页面错误向用户提供可执行信息，详细异常仅记录不含密钥的安全日志。

## 11. 测试与验收

自动化测试覆盖：

- CSV 正常解析、必填字段、非法日期/评分、空文本、文件限制和重复去重。
- 六类离线规则、冲突规则、未命中待确认和影响程度边界。
- DeepSeek 合法响应、非法 JSON、非法枚举、超时和回退路径。
- 国家、用户类型、商品品类与日期组合筛选。
- 优先级公式、稳定排序、待确认排除和 Top 5 截断。
- 人工修订及修订记录。
- 需求卡创建、编辑、状态校验、筛选、归档与恢复。
- SQLite 重启持久化和事务回滚。

浏览器验收覆盖完整主路径：从空库下载模板、导入一批测试反馈、筛选、修正分类、查看 Top 5、创建需求卡、更新状态，并在应用重启后确认记录仍存在。
